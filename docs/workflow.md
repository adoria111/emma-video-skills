# 从直播到发布：六步使用指南

## 1. 开启直播或线上课程

正常分享和答疑，保留原始录屏。尽量让讲者声音清楚，演示内容可读；多人连麦时保留区分说话人的信息。公开使用素材前确认自己有相应权利，学员提问可去除姓名和联系方式。

不要求你先把内容改写成完美逐字稿。真实问答里的例子和判断过程，往往就是剪辑的主要素材。

## 2. 导出录屏或视频切片

可以给完整录播，也可以给已有切片。保留原件，避免反复覆盖。建议采用简单目录：

```text
my-session/
├── source/           原录播或已有切片
├── transcripts/      与素材对应的 TXT、SRT 或 VTT
└── delivery/         每条成片、字幕、封面及文案
```

告诉 AI 哪些文件是同一段内容的重复导出，哪一版是你已经检查过的版本。不要用文件名里的“最终”代替实际确认。

## 3. 导出逐字稿

已有得到大脑、剪映等工具生成的逐字稿，可以直接提供。带时间的 SRT / VTT 更便于定位；TXT 也能用于拆选题，但没有时间时不能靠字数猜切口。

没有逐字稿时，使用 `video-transcribe`。附带脚本调用本机 `faster-whisper`，输出 TXT、SRT 和含逐词时间的 JSON。首次模型下载需要网络，实际音视频转写在本机执行；模型和第三方包不随仓库分发。

自动识别只是初稿。姓名、平台名、数字、术语及“收稿／手稿”等近音词要回到原声和上下文核对。

## 4. 安装 Skills 和剪辑能力

先按 [安装说明](install.md) 安装六个 Skill，再选择实际剪辑工具：**ChatCut、剪映无界面方案或你已有的剪辑器**，不必同时安装。按 [依赖说明](dependencies.md) 打开对应官方入口，核对环境、接入方式和使用条款。

选择 ChatCut 时，可用它完成剪辑、字幕和成片导出；需要 AI 助手直接操作时，另按官方 Agent Plugin 指引接入。之后想在剪映里精修，可从 ChatCut Desktop 导出可编辑草稿，并在剪映中检查不支持的效果和字幕。用户已经修改过的剪映工程，应先确认所选工具能否接续该版本。

不会写代码也可以把仓库链接交给具有文件操作能力的 AI，要求它按说明安装。安装器不下载剪映、不登录账号、不购买资源、不修改授权机制。

若当前环境只能读文字，可以先完成选题和剪辑单，但这不能称为“已剪好视频”。图片生成能力缺失时，也应交付明确的封面规格并说明缺少的执行条件。

## 5. 视频、逐字稿和目标一起交给 AI

最有用的信息是：给谁看、要完成什么目的、哪些内容必须保留、偏好的时长，以及是否需要可编辑工程。普通排版和命名可以交给 AI 判断。

同一条视频尽量回答一个核心问题；合集里的问答要相关，不能为了凑数拼在一起。跨片段组合时，检查提问、指代、案例和答案是否完整。原话定位要保留素材名、源时间和首尾句。

开始执行后，AI 应在授权范围内推进到交付，不把每个内部批次都当作必须重新批准的节点。真正缺少会改变目标或结果的输入时，才集中询问。

## 6. 精修、封面、文案和发布

先检查成片及字幕，再以这一版制作封面、正文与标题。每张封面的底图取自它对应的成片或能够映射回成片的原始片段；样式参考图中的人物不能混入新底图。

如果你又去掉了水词、调整顺序或换了片段，把最新工程交给 AI，按 [字幕同步说明](subtitle-sync.md) 校准。你说“检查完了，导出吧”之后，应导出这一最新版本，而不是上一次准备好的旧快照。

建议每条交付：

- 最终 MP4、匹配 SRT 和可用的可编辑工程。
- 对应封面及其底图来源。
- 发布正文、标题和适用时的章节时间。
- 必要的版本说明：哪一个已检查、哪一个已导出。

完成文案不等于已经在社交平台发布。只有你明确授权了平台、账号和要发布的内容，且宿主工具允许时，AI 才能实际执行发布。
