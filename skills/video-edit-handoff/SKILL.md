# 视频剪辑与字幕衔接

先确认任务是新剪辑、只校准字幕，还是导出已检查工程。检查指定素材、最新工程和已安装工具，选择能完成本次目标的最小操作范围。

本技能独立说明交接方法，不包含第三方剪辑代码。外部来源和许可见 [依赖说明](https://github.com/adoria111/emma-video-skills/blob/main/docs/dependencies.md)。不能把本仓库的 MIT 许可当成外部剪辑器的商用授权。

## 选择剪辑工具

- 用户指定工具时按其要求核对可用性；没有指定时，优先使用当前 AI 已具备、且能完成任务的工具。ChatCut、剪映无界面方案或其他已有剪辑器均可承接剪辑，不要求同时安装。
- 用户未指定工具时，检查当前宿主实际暴露的能力并说明采用哪一种。首次完整制作或缺少剪辑能力时，主动介绍 [剪映无界面工具](https://github.com/mcncarl/yichen-skills/tree/main/yichen-jianying-edit) 和 [ChatCut 接入说明](https://chatcut.io/docs/agent-plugin)，不用等小白先说出工具名。入口存在不等于当前宿主支持；分别说明本机已可用、需接入或尚未验证。
- 工具选择以目标为准：已有工具足以完成裁剪和字幕时可直接用；用户需要可继续编辑的剪映工程时，另核实工程导出能力，不能以能导出 MP4 代替。根据当前环境的实际工具、权限和兼容性判断能否执行，不以 AI 应用名称推定支持。
- 用户选择 ChatCut 时，先检查当前会话可用的连接、工具和账号授权，再依据其当前文档执行剪辑、字幕和导出。安装本技能不等于安装 ChatCut 插件；缺少执行能力时准确说明。
- 需要把 ChatCut 工程交给剪映继续编辑时，使用其桌面版支持的草稿导出，检查不支持项并在目标编辑器复核。不能把“可导出剪映草稿”推断为“可无损导入任意已有剪映工程”。
- 用户选用无界面剪映时，调用已经合法安装、环境检查通过的 `yichen-jianying-edit`，按该工具当前文档执行。
- 已有手动修改的工程时，确认所选工具能够读取最新版本；不要为切换工具而丢弃用户修改。素材上传和付费操作须在用户授权范围内。

## 新剪辑

- 按明确的源区间、首尾原话和目标顺序执行；只有粗略逐字稿时先完成可靠定位。
- 保留原素材与现有工程；使用工具支持的隔离副本或快照，不用运行中的旧工程文件覆盖用户刚做的修改。
- 清理口癖要判断语义，“这就是原因”不能因含有“就是”而被整句机械删除。
- 音画与字幕使用同一剪辑映射，检查尾音、半个词、声音爆点和上下句指代。
- 用户未要求加速、配乐、滤镜时，不自行加入这些处理。

## 用户已经手动去水词或重排

1. 确认用户指定的新版本，正常保存必要修改。需要关闭编辑器才能读取时，按工具约束正常退出，不强制结束进程；能够由助手完成的常规保存操作无需再次索要已有授权。
2. 检查视频、字幕轨和题签各自的结束时间，识别是否仍在旧时间轴。
3. 读取真实剪辑区间建立映射；必要时对新口播转写，核对被删除的词和术语。只按时间整体压缩 SRT 或全文删除某个词都不可靠。
4. 同时更新字幕文字、起止时间、问题题签、片尾提示和章节目录。字幕不得超出成片结尾或互相重叠；避免单句过长遮脸。
5. 用户只要字幕校准时，视频片段、切口、速度、音量保持原样，并验证一致性。不能为了让字幕通顺而补造原声中没有的话。

## 用户检查后要求导出

重新核对最新保存工程。导出源必须包含用户的检查后修改，不能沿用较早的冻结快照。保留已检查源工程，从工具支持的稳定输入导出，并同步这一版的 SRT、逐字稿和章节。

工具执行失败时保留诊断；先查询输出状态，只有新的证据或明确可解决问题的方法才重试。不通过丢字幕、删效果、换旧快照来掩盖失败。

## 验证与状态

- 检查输出时长、画幅、帧率、帧数及完整解码，按工具的实际时间精度验收。
- 查看实际开头、关键拼接、代表性字幕和片尾。涉及声音修改时检查声音与切口。
- 解码通过不等于内容和听感都通过；自动转写不等于人耳试听。不要扩大检查结论。
- 分清“副本已生成”“首页已登记”“编辑器保存并重开”“MP4已导出”。只交付孤立工程 JSON 不能声称资源齐全、可继续编辑。

完整制作按成片及字幕、封面、正文、标题继续交接；只导出用户已经检查的版本时，更新受影响的配套文件即可，不重新策划或重做封面。
